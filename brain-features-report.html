01 Architecture at a glance

Six layers, one deployed Worker. Every request resolves a tenant-scoped Principal at the edge, dispatches through a single op-registry shared by all surfaces, and touches storage only through tenant-scoped service wrappers that re-check isolation in D1 on every read.

The isolation invariant. Multi-tenant safety does not rest on the Vectorize namespace or the Durable Object boundary. Every retrieved chunk/fact is re-checked for tenant_id ownership in D1 before it is returned — and a mismatch is silently dropped, never errored. An adversarial fake vector index is part of the test suite to prove cross-tenant content can never leak.

02 Core capabilities

What the platform does, grouped by domain.

📥 Ingestion & document loading

Paste or upload Markdown, plain text, HTML, PDF, DOCX, and images. Binary/HTML is converted to Markdown via Workers AI toMarkdown. Content is fingerprinted (SHA-256, formatting-insensitive) for durable dedup, stored in R2, chunked heading-aware, embedded, and indexed — all inside a durable BatchIngest Workflow. Documents carry an add-date, comma-separated tags, and a path namespace (e.g. /project/x).

🔎 Hybrid search & cited synthesis

Vector (bge-m3, 1024d cosine) + full-text (D1 FTS5) retrieval, fused and reranked (bge-reranker), then synthesized into a cited answer (Llama 3.3 70B) by think. Retrieval can be scoped to a path namespace or a tag, so an agent can ask questions within /project/x only.

🕸️ Knowledge graph

Entities and relations are extracted from chunks (EntityExtraction Workflow) into a queryable graph: traverse, links/backlinks, tags, timeline, orphan detection, and semantic entity search — surfaced as an interactive force-directed graph in the dashboard.

🧠 Sessions & hot memory

Live turns are captured to a lean D1 row + R2 transcript. On finalize (or an idle-promotion cron), a SessionPromote Workflow distills durable facts. Hot-memory recall is visibility-gated, and memory_review is the only path that promotes a fact to a trusted instruction.

🏢 Organizations & access

Create and switch between orgs, add members by email (live Clerk directory lookup), edit roles and scopes, and remove members — with a last-owner guard. Every write records which user added it across REST, MCP, and the web.

🔑 API keys & auth

Full CRUD on bk_ API keys (raw token shown once, then hashed). Three auth paths converge on one Principal: Clerk OAuth/JWT, API keys, and HMAC device tokens for headless CLI login.

🛡️ Governance & audit

Append-only memory_audit on every mutation (actor recorded), tamper-evident R2 audit export, admin-only break-glass reads that fail closed and are always audited, per-tenant token-spend ceilings, and trust grading on facts.

🔌 Backfill & sources

Queue-driven backfill with an Enumerator Workflow, exponential-backoff source sync, and a re-embed sweep — so large corpora and model changes are absorbed durably off the request path.

03 Four surfaces, one registry

Every capability is defined once as an op (name, Zod schema, capability, surface set) and projected onto all surfaces. The build fails if any surface drifts from the registry.

🖥️ Web Dashboard

TanStack Start + shadcn on Workers. Search/Think, Documents catalog (with tag/path/date filters & an "Added by" column), Add-Document, Graph, Sessions, Members, API Keys, Admin/Stats, Audit, Jobs — plus an org switcher, a click-to-copy MCP URL, and a responsive mobile nav.

🤖 MCP Server

Agent-facing Model Context Protocol at /mcp and per-tenant /mcp/:slug (Durable-Object stateful + stateless Streamable-HTTP). Connect via OAuth 2.1 ("Connect with OAuth", Clerk-backed, PKCE, dynamic client registration) or a bk_ bearer.

⌨️ CLI

A typed tRPC client over the same registry, grouped into help sections (search, graph, session, facts, key, admin). Headless login via the RFC 8628 OAuth device flow.

🌐 REST API

Direct HTTP endpoints (/ingest, /documents, /think, /graph/*, session & governance routes) behind the same edge-resolved Principal and tRPC catalog.

05 Data model & storage

A single shared D1 is the tenancy spine; large bodies live in R2; vectors live in Vectorize.

Content

  • documents — slug, body→R2, fingerprint, tags, path, status, provenance
  • chunks — heading path, tokens, path, FTS5-indexed
  • facts — distilled hot memory, trust-graded

Tenancy & auth

  • orgs · memberships — roles, scopes, created_by
  • api_keys — hashed, scoped, revocable
  • tenant_shards · CLI auth/refresh tokens

Graph

  • entities · entity_relations · entity_mentions
  • doc_graph nodes / edges (wiki-links)

Sessions

  • sessions · session_turns — lean rows + R2 transcripts
  • brain_snapshots — frozen context
  • memory_use_policy · memory_review

Governance

  • memory_audit — append-only, actor-stamped
  • memory_recall_traces — off-path recall log
  • token_spend — per-tenant cost ledger

Pipeline

  • ingest_log · backfill_runs
  • sources — backoff-synced importers

06 Models & engineering

AI models (Workers AI via AI Gateway)

  • Embedding — @cf/baai/bge-m3 · 1024d
  • Generation — llama-3.3-70b-instruct-fp8-fast
  • Rerank — @cf/baai/bge-reranker-base
  • Extraction — llama-3.1-8b-instruct
  • BYO provider — OpenAI-compatible endpoints supported

Engineering discipline

  • Turborepo + Bun workspaces; 8 packages, deletable in isolation
  • Biome (strictest) + TypeScript strict; bun check gates every change
  • Boundary-lint: raw CF bindings only inside packages/db
  • Drift tests: registry ↔ catalog ↔ every surface stay in lock-step
  • Adversarial isolation canary in the test suite
