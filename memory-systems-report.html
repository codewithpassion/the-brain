01The blueprint the video describes

Simon defines "perfect memory" for a business as four capabilities, each cherry-picked from a different open-source project. Claude Code out of the box is weak at all three core jobs — storage, injection, and recall — so the goal is to assemble the best of each.

Pillar 1 · from GBrain
Cites its sourcesReturns the exact conversation context, the words used, the file/line, and the date. Synthesizes a cited answer — and admits when it doesn't know instead of inventing.
Pillar 2 · from Hermes
Recent-context injectionA small, capped "frozen snapshot" (soul / user / memory / today) loaded silently at session start via a hook. Avoids context rot.
Pillar 3 · from memarch / vectors
Long-term search by meaningChunk → summarize/keep verbatim → embed → hybrid vector + keyword search. "Payment processing" finds "Stripe" even with no shared words.
Pillar 4 · from GBrain company brain
Scoped team / client accessOne shared brain, every memory tagged by owner, every query filtered by who's asking — enforced by row-level security.

The runtime loop Simon describes

A Stop hook fires after every turn → decides if the turn is a durable fact (decision, price, preference, environment) → promotes it into a capped short-term memory.md (dedup/overwrite) and embeds everything long-term regardless. Retrieval is three-tier: (1) read the injected short-term snapshot → (2) if absent, vector + keyword search top 5–10 → (3) rerank, then synthesize a cited, honest answer. A one-time backfill turns months of old sessions into memory so you "start with everything already remembered." Team OS = Railway Postgres with row-level security (or local PGLite + pgvector).

02The three building blocks

Each project is real, deployed, and substantially complete. They are not three attempts at the same thing — they specialize. Below: what each is, and the one job it does better than the others.

cf-graph

Document & knowledge-graph engine on Cloudflare Workers. Ingests PDF/DOCX/HTML/CSV, converts to Markdown, chunks, embeds, and auto-extracts an entity/relationship graph.

Stack: TS · Workers · D1 (SQLite) · R2 · Vectorize · Workers AI (bge-m3 1024d, llama-3.1-8b). Hono · TanStack · tRPC · Clerk.

  • Hybrid search (vector + FTS5 + RRF) on both chunks and entities
  • Durable, resumable ingestion Workflows — retried per-step, survive restarts
  • KG extraction with truncated-JSON recovery
  • Workspaces + per-user ownership (app-level), read-only API keys
  • cfg CLI + workspace-scoped MCP (read/mutation tools)

Best at: heavy, reliable ingestion of arbitrary documents into a searchable graph.
Missing: no session/conversation memory, no context injection, no synthesized/cited answers, no "I don't know."

gbrain-cf

The GBrain reimplementation — a "company brain" MCP server (47 tools) on Cloudflare. Markdown pages + typed link graph + hot-fact memory + cited synthesis.

Stack: TS · Workers · D1 · Vectorize (gbrain-chunks 1024d) · Workers AI (bge-m3 + llama-3.3-70b). OAuth 2.1 via Clerk · cron job runner.

  • think — hybrid search → LLM synthesis → cites slugs, reports gaps, admits "no evidence"
  • Hybrid search + LLM query expansion (RRF, compiled-truth & title boosts, staleness flag)
  • Typed fact hot-memory — extract_facts/recall/forget_fact, with kind/confidence/notability/visibility/validity
  • Graph — typed links, BFS traverse_graph (depth 10), backlinks, tags, timeline
  • GitHub source sync + webhook ingest + async job queue

Best at: Pillars 1 & 3 — cited synthesis and meaning-based retrieval. The closest thing to "perfect memory" already built.
Missing: single-tenant (no per-user / per-client row-level isolation), no client-side injection hook.

openbrains

Multi-tenant governed-memory SaaS. Remote MCP + CLI + dashboard so any AI client captures, searches, and recalls thoughts with full provenance and trust grading.

Stack: TS · Convex (reactive DB + auth) · Vectorize (thoughts-v1, namespace = userId) · Workers AI (qwen3-embed 1024d). OAuth 2.1 via Clerk · CLI ob.

  • Strict per-user isolation — Convex requireUserId + Vectorize namespace=userId (cross-tenant query impossible by construction)
  • Trust grades — instruction / evidence / draft; agent writes hard-wired to evidence; only humans promote to instruction
  • Full audit — memory_audit diff log + memory_recall_traces per query
  • Project scoping (per-project namespaces, global entity/CRM graph)
  • Capture primitives: brain-dump split, agent writeback, Gmail/OB1 importers

Best at: Pillar 4 — multi-tenant scoping & governance done properly.
Missing: vector-only (no hybrid / no rerank), no synthesized cited answer, no hot-fact snapshot store, no injection hook.

The blueprint asks for one project per pillar. Strikingly, we already own a best-in-class implementation for three of the four — and the fourth (Hermes injection) is deliberately a client concern, not a server one.

The core tension to resolve

gbrain-cf has the retrieval brain (citations, hybrid search, hot facts, graph) but is single-tenant. openbrains has the tenancy & governance (per-user RLS, trust grades, audit) but is vector-only with no synthesis. The video wants both from "GBrain." So the decision is: which one becomes the spine, and which one donates its missing half?

05What's missing across all three

Even combined, the three projects leave four concrete gaps versus the blueprint. These are the actual build work.

① Session-start injection hook Pillar 2

None of the three servers injects a capped frozen snapshot — correct, it's a harness job. But it is not greenfield: bruce-hermes*/reference/hermes-agent/ holds the Hermes reference (SOUL.md "loaded fresh each message," hermes_cli/subcommands/memory.py + profile.py, profile-builder.md) and bruce-reborn/ has a TS hooks framework. Work = adapt that into a SessionStart hook in bruce/agent that pulls a byte-capped soul / user / memory / today bundle from gbrain. The main agent's .claude/ has settings + skills but no snapshot hook yet.

② The Stop-hook promote/embed loop Runtime

No project has the after-every-turn judge that decides "is this a durable fact?" then promotes to short-term and embeds long-term. gbrain's extract_facts + openbrains' writeback are the primitives; the orchestration belongs in a Bruce Stop-hook.

③ Per-user RLS inside the retrieval brain

gbrain-cf (the best retrieval brain) is single-tenant. To deliver Pillar 4 you must add an owner/scope column to D1 + a Vectorize namespace per identity + token→identity scope filtering — exactly the model openbrains already proves.

④ True reranking

All three stop at RRF fusion + heuristic boosts. The video explicitly calls for a rerank step before synthesis. A cross-encoder or LLM rerank over the top 10–20 candidates is a small, high-leverage addition to gbrain's think.

Why gbrain-cf as the spine (not openbrains) — and the risk to weigh

Two of the four pillars — cited synthesis and hybrid meaning-search — are the hardest to build, and gbrain-cf already nails both, plus the hot-facts store and graph traversal. Both run on the same Cloudflare D1/Workers/Vectorize substrate, so cf-graph and gbrain compose natively.

The asymmetry to respect: the gbrain→openbrains gap is additive and safe (add synthesis/hybrid; worst case is weaker search, nothing leaks). The openbrains→gbrain gap is security-critical — retrofitting multi-tenancy into a single-tenant brain means every future query must remember to scope, and isolation bugs leak silently across clients. openbrains made cross-tenant access impossible by construction (requireUserId at the identity layer, namespace=userId at the Vectorize layer); that is hard to replicate as a retrofit. So if a multi-tenant team brain ships soon, lean openbrains and frame the call on isolation risk, not effort.

Decision rule: single power-user / personal brain (Pillar 4 deferred) → extend gbrain — clearly right. Paying multi-tenant team needed soon → extend openbrains as the tenancy shell and port gbrain's think + hybrid + facts in; you inherit production-grade Convex auth + audit from day one. Note these are different substrates (Convex vs D1), so either direction is a reimplementation of the pattern, not a code lift.

07Phased build plan

Ordered so you get a usable multi-layer brain after Phase 2, with team scoping and backfill following.

  1. ~2–3 days · Bruce

    Wire gbrain-cf as Bruce's memory backend + the Stop-hook loop

    Point Bruce at gbrain's MCP. Add a Stop hook: after each turn, call extract_facts; for durable items (decision/price/preference/env) write to the facts store with dedup, and let put_page/embedding handle long-term. This alone fixes Claude's storage gap.

  2. ~2–3 days · Bruce (adapt, not build)

    Hermes-style SessionStart injection (Pillar 2)

    Adapt the existing Hermes reference (bruce-hermes*/reference/hermes-agent/ — SOUL.md, memory.py/profile.py, profile-builder.md) and the bruce-reborn TS hooks framework into a SessionStart hook in bruce/agent. Snapshot = soul + user from static brain pages, memory from a byte-capped recall of top recent facts, today from today's timeline entries. Inject silently; hard cap (e.g. ≤2k tokens). Check first whether bruce-reborn already wires snapshot injection — if so this shrinks further.

  3. ~1–2 days · gbrain-cf

    Add a rerank stage to think (gap ④)

    Between RRF fusion and synthesis, rerank the top 10–20 candidates with a cross-encoder (or a cheap LLM rerank). Measurable retrieval-quality win; completes the video's "rerank then cite" step.

  4. ~2–3 days · cf-graph → gbrain

    Session-history backfill

    Write an adapter that feeds existing Claude session transcripts through cf-graph's durable ingestion Workflow (chunk → embed → KG), writing into the shared core. This works because cf-graph and gbrain both embed with bge-m3 1024d — vectors are directly compatible. The effort is re-targeting cf-graph's document/chunk model onto gbrain's page/chunk schema + Vectorize index, not the embedding. Run once: "start with everything already remembered, searchable, cited."

  5. ~1.5–2 weeks · gbrain-cf (reimplement openbrains' pattern)

    Per-identity scoping + trust grades (Pillar 4 / Team OS)

    Security-critical, and a reimplementation — not a code lift (openbrains is Convex, gbrain is D1). Replicate openbrains' model on D1: owner + scope columns on pages/facts/chunks, a Vectorize namespace per identity, token→identity resolution, and query filtering that is enforced at a single choke-point (mirroring openbrains' requireUserId + namespace=userId "impossible by construction" design) rather than per-query. Add instruction/evidence/draft trust grades + memory_audit + recall traces. Budget time for isolation tests that actually prove cross-tenant access fails. This is the company-brain / Railway-RLS equivalent the video defers to "next few weeks."

  6. ongoing

    Non-technical contribution + version control

    Let brand context & CLAUDE.md live in Notion / Google Drive as source-of-truth, synced into the brain (gbrain already has GitHub source sync as the pattern). Back everything to GitHub. Skills/memory stay agent-managed.

One-line summary

gbrain-cf is your GBrain (Pillars 1 & 3, already done) → borrow openbrains' governance for Pillar 4 → use cf-graph to backfill the long-term store → build the Hermes snapshot + Stop-hook in Bruce for Pillar 2 and the runtime loop. That assembles the exact four-pillar, three-tier memory the video describes — mostly from parts you already own.
